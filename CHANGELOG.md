# Changelog

## Unreleased

### Security and robustness

- Running any tool (C-ECHO, C-STORE, C-FIND, MWL C-FIND, HL7 send, PDF to DICOM, testbench) from the browser crashed with `display_tool_name is undefined` instead of showing the result. The HTMX partial that renders results needed it and three routes were passing it a minimal template context that didn't include it.
- **Dicom Anonymizer**: the sidebar was showing the full Dicommunication navigation — Testbench, C-ECHO board, Worklist, every test tool — instead of the slim single-tool sidebar Dicomtag Analytics gets (its own page, Configured nodes, Logs). `base.html` only special-cased `shell == "vue"` for the slim sidebar; every other shell, Dicom Anonymizer included, fell through to the full one. Generalized to `shell != "dicommunication"`, so any future single-tool shell gets the slim sidebar automatically too.
- **Windows uninstall**: MSI uninstall only removes what it installed under Program Files, never `%LOCALAPPDATA%\dicommunication` — the running app writes there itself, so it survived uninstall silently. Uninstall now asks once whether to also delete it, since it can hold patient data (see `SECURITY.md#patient-data-on-disk`); the default answer keeps it, same as before this prompt existed. Never fires during an upgrade (only a genuine uninstall) or a silent/unattended one.
- **Windows install**: a manual MSI rebuild without bumping the app version installed side by side with whatever was already there (WiX's `AllowSameVersionUpgrades` defaults to off) instead of replacing it, which is how a stale **Vue PACS Database Analytics** Start-menu shortcut kept surviving reinstalls. Turned that on, bumped the app to 0.4.0, and added an explicit cleanup of that old shortcut name on every install so a machine that already has the stray entry gets it removed too, not just future ones.
- **Windows install**: the setup wizard now shows a feature tree instead of just an install-folder picker (`WixUI_FeatureTree`). Dicommunication and Dicomtag Analytics are separately checkable Features — both on by default, matching today's behavior — and each has an off-by-default **Desktop shortcut** sub-feature, since the Start Menu shortcut already covers the common case. Unchecking one app only drops its own Start Menu shortcut; the underlying program files are shared (both are the same `dicommunication.exe`, just a different `--profile`) and stay installed as long as either app Feature is selected.
- **macOS DMG**: now ships two fully independent, self-contained app bundles — `Dicommunication.app` and `Dicomtag Analytics.app` — instead of one app plus a documented `--args --profile` workaround for the second tool. Either can be dragged onto Applications (or the Desktop, for a shortcut) without the other; a plain double-click opens the right profile (`Info.plist`'s `LSEnvironment` sets `DICOMM_PROFILE`, which `launcher.py`'s `--profile` flag already fell back to). Both are built from the same PyInstaller `COLLECT` output, so the DMG is roughly twice the size but the build itself doesn't take twice as long. They still share one background server: opening the second app while the first is already running just adds a window rather than starting a second server.
- **Dicom Anonymizer** now has the same Windows MSI and macOS DMG treatment as Dicomtag Analytics: a third checkable Feature (`DicomAnonymizer`) in the MSI's feature tree with its own Start Menu shortcut, off-by-default Desktop shortcut sub-feature, and `--profile dicom-anonymizer` argument, sharing the same `AppFiles` component as the other two; and a third self-contained `Dicom Anonymizer.app` bundle in the DMG, built from the same `coll`, with its own `LSEnvironment: DICOMM_PROFILE=dicom-anonymizer` for a plain double-click.

- Added [`SECURITY.md`](SECURITY.md): threat model, the list of things that have no protection by design (so they stop being re-reported), which patient data ends up on disk and where, and how to reproduce the dependency and static-analysis checks. Added a Dependabot config for pip, GitHub Actions, and the Docker base images.

- A `config.json` that cannot be read (truncated write, bad hand-edit, schema change) no longer stops the app from starting. The unreadable file is kept as `config.corrupt-<timestamp>.json` so remotes can be recovered by hand, and the app carries on with defaults. Individual unreadable worklist / result / HL7 records are skipped instead of hiding the whole list.
- **PDF to DICOM**: a ZIP the tool cannot decode now reports a readable error instead of failing the request outright, scanning a folder no longer walks the whole subtree before applying the depth limit, and a batch over the 40-file cap is rejected without first reading every upload into memory.
- **Docker**: Compose published the login-less web UI on every interface, which contradicted the README's own advice not to expose port 8080 without an authenticating reverse proxy. It now publishes `8080` on `127.0.0.1`; set `DICOMM_HTTP_BIND=0.0.0.0` to open it up deliberately. The MWL SCP port `11112` stays on every interface so a modality can still C-FIND this workstation, and `DICOMM_DICOM_BIND` pins it to one address on a multi-NIC host. Startup logs which address the UI was published on and how to change it, so `docker compose logs` explains a UI that will not load from another machine.
- htmx is served from the app (`/static/vendor/`) instead of `unpkg.com`. The desktop builds no longer need internet for buttons to work, and a CDN cannot change what runs in the UI.
- Dependency floors moved off releases with published advisories: `jinja2` 3.1.6, `python-multipart` 0.0.31, `pydicom` 3.0.2, `fastapi` 0.135 (the previous `<0.129` cap held `starlette` on a 0.x line whose `StaticFiles` UNC-path and form-limit fixes only exist in 1.x), `pytest` 9.0.3.
- `POST /api/remotes`, `/api/identities`, `/api/worklist` and `/api/hl7/messages` assign their own record ids. Supplying an `id` used to be possible and two records could share one, after which a delete removed both.
- **Worklist**: patient-name search now follows the DICOM wildcard rules. `?` matches exactly one character (it was ignored unless the query also had a `*`), and `[`, `]`, `.` are literal characters rather than pattern syntax.
- **Windows installer**: the Dicomtag Analytics Start-menu shortcut kept its old MSI component GUID when it was renamed from Vue PACS Database Analytics, so upgrading left the stale `Vue PACS Database Analytics.lnk` behind alongside the new one instead of replacing it. The component now has a fresh GUID so the next upgrade retires the orphaned shortcut.
- **Windows MSI** and **Docker image** CI workflows no longer build on every push to `main` or on pull requests — like macOS DMG, they now only run from **Actions → Run workflow**.

### Interface

- **Dicomtag Analytics**: six fixes/polish items from live use of the new Study Date picker and query results.
  - The **Today** / **Yesterday** / **Last 7 days** / **Last 30 days** / **This month** / **Clear** preset buttons did nothing when clicked. The date-tools box stops clicks from bubbling to the parent `<label>` (so blank space doesn't toggle its "include as return column" checkbox), but that `stopPropagation()` also silently swallowed the click before it ever reached the delegated handler that applies the preset — now the box applies the preset itself before stopping propagation.
  - The focus border on inputs/selects (the gradient ring shown while editing a field) is thicker (1.5px → 3px) so it reads clearly instead of being a thin line.
  - The **Stop** button (shown while a query is running) is now red instead of the default neutral button color, so it's unambiguous which button cancels the query.
  - **List SR reports** and **Retrieve report text** replaced the results panel with no way back to the original query results table. Added a **← Back to results** button on both follow-up views that restores the previous view (client-side, no re-query) — a stack, so retrieving report text from the SR list and going back returns to the SR list, and going back again returns to the original table.
  - Structured Report contents (the retrieved report cards) had no way to jump to a specific patient in a long list. Added a search box that filters both the overview table and the report cards together by patient name, ID, accession number, document title, findings, or impression text.
  - A query that hits the 2000-row display cap now shows a proactive confirmation banner ("Continuing could have a significant impact on the performance of the PACS") with a **Continue anyway** button instead of silently staying capped or (for Count patients by name) silently auto-re-querying without the cap — both now require this same explicit opt-in before re-querying up to 50000 rows.
- Rebranded the sidebar/topbar mark and every installed app icon (Windows `.ico`, macOS `.icns`, browser favicon — Docker has no separate OS-level icon, so the favicon covers it too) from the Sansation Bold "A" glyph to the arnout.pro brand mark (multicolor geometric "A"), sourced from [`arnoutpro/pacsadministration`](https://github.com/arnoutpro/pacsadministration)'s `public/icon-512-transparent.png`. The topbar mark was previously a live CSS aurora-gradient animation clipped to the glyph; since the new mark is already a static multicolor image, that animation (and the JS that kept its clip-path in sync with font loading) is gone, replaced by a plain image using the same `favicon.svg` that also feeds the installer icons.
- The main content column was capped at `max-width: 1100px` on every page except Logs and Dicomtag Analytics, which had already opted out (`max-width: none`) — so every other page (Dicom Anonymizer, Tag Editor, Configuration, Testbench, Worklist, the Dashboard) stayed a fixed, comparatively narrow width no matter how wide the browser window actually was. Raised the default to `1600px`, which noticeably reduces the wasted space on a normal 1440–1920px desktop window without making two-column forms uncomfortably wide.
- **Dicom Anonymizer**: new third product — `--profile dicom-anonymizer` (or `python -m app --profile dicom-anonymizer`) mounts it at `/anonymize/`, same pattern as Dicomtag Analytics, with its own Windows MSI Start Menu / Desktop shortcut and macOS `Dicom Anonymizer.app` bundle (see the Windows install / macOS DMG entries above). Study-level C-FIND on Patient ID / Accession Number / Study Date (required) / Modality, then pick which studies to anonymize and at what level: **Study** anonymizes exactly the checked studies; **Series** or **Image** C-MOVEs every series or image inside them (v1 has no per-series/per-image picker yet — check only the studies you actually want). Four modes: **Nuke** rebuilds each instance from only the tags a DICOM viewer needs to open it (Rows, Columns, pixel data, fresh Study/Series/SOP Instance UIDs) and drops everything else; **Fuzz** keeps every tag but scrambles its value, leaving pixel data and image-structure tags alone so it still decodes; **Remove patient information** only touches a curated list of ~50 patient-identifying tags (roughly DICOM PS3.15 Annex E), erased or scrambled; **Custom** exposes that same tag list, grouped by category, for a per-tag keep / erase / replace-with decision. Every mode routes Study/Series/SOP Instance UIDs through one shared map per run, so instances that shared a UID before anonymizing still do afterward instead of each landing in its own orphan study. Output is loose `.dcm` files in a new subfolder, or a ZIP (7z is not implemented yet); every file and folder name is built from the anonymized UIDs, never the originals, so a filename can't leak PHI regardless of mode.
- **Tag Editor**: new tool. Corrects `Tamar Report Final Sign Timestamp` (07a3,10fb) and `Tamar Report Study Last Composed By` (07a5,1040) — private ELSCINT1 tags CS PACS REPORT writes onto every instance in a study — for reports stuck because one of them didn't get set, then C-STOREs the fix back. **Seed test studies** C-STOREs two throwaway studies (patient `ARNPRO^TESTBENCH`) — one with both tags present but blank, one with them entirely absent — so Push can be tested against the actual missing-data case without touching a real patient; needs no Accept C-STORE, same as the C-STORE test tool. **Find Study Instance UID** resolves it from Accession Number and Study Date (both required) via a plain C-FIND, no Accept C-STORE needed for that step. **Fetch** C-MOVEs the study (or one series) and shows current values per instance; **Push** overwrites only the field(s) given and re-stores every retrieved instance, since Vue mirrors both tags across the whole study. Only ever overwrites a tag that is already present — never invents one on an instance that never had it; if the real stuck case has the tag entirely absent rather than present-and-blank, Push can't fix it as built. The local Storage SCP now also accepts common image SOP Classes (CT, MR, DX, CR, US, Secondary Capture, NM, PET, XA, RF, mammography) alongside Structured Reports, so this and future retrieve-based tools aren't limited to SR. **Fetch now shows `(present, empty)` vs `(not present)` for these two tags** instead of the same blank cell for both — that distinction is exactly what decides whether Push can do anything, so it needs to be visible. Tested once against a real Vue archive, but only on an already-complete study: C-MOVE and C-STORE both reported success without the stored object actually changing — that shows Vue ignores a C-STORE that changes an already-filled field, not what happens with a genuinely missing value (Seed test studies exists to check that). A separate distribution log shows these two fields are required input to Vue's own report-distribution step, not something an inbound HL7 message could supply — so an HL7-based fix isn't a workable direction; a re-open/re-sign action in Vue's report UI, or a Philips/Vue support escalation, look more promising.
- **Dicomtag Analytics**: Modalities in Study is now a row of toggle chips for the common codes (CR, CT, DX, MG, MR, NM, OT, PT, RF, SC, SR, US, XA) instead of a single free-text box — pick several (for example CR and DX) to match any of them, since `ModalitiesInStudy` is a multi-valued DICOM key on the wire regardless of UI. The text field underneath is still there for uncommon codes and stays in sync both ways (typing into it checks the matching chips; checking chips writes the backslash-joined value into it). Study Date gets preset buttons (Today, Yesterday, Last 7/30 days, This month) and a From/To date picker on top of the same text field, which still takes manual DICOM date syntax (single day, or an open-ended range) for anything the pickers can't express.
- **Dicomtag Analytics** is the new name of the second Start-menu tool (was Vue PACS Database Analytics). Window title, Help, About, README, and the MSI shortcut match. `--profile dicomtag-analytics` opens it; `vue-analytics` still works.
- README screenshots of the Dicommunication dashboard and Dicomtag Analytics (query + Structured Report retrieve). Synthetic lab studies, not clinical data.
- **Dicomtag Analytics**: retrieve C-MOVEs each listed SR on its own association (Vue often accepts only one C-MOVE per association, which previously returned a single patient’s report). The buttons show the study / series count. The summary is Retrieved N of M. List / retrieve use the full result table, not a Study Instance UID left in the query form. Cap is 200 studies and 200 series. Copy / CSV / JSON read a hidden textarea so the buttons work after HTMX swaps.
- **Dicomtag Analytics**: retrieve error names the listen AE Title and port Vue must use as C-MOVE destination, and says Present as (virtual calling AE) is not that destination. Query shows when SR C-STORE is off, with a link to Local DICOM AE.
- **Dicomtag Analytics**: **List SR reports** after a Study query (Series C-FIND, modality SR, same Study Instance UID). **Retrieve report text** C-MOVEs those series to this AE when Accept C-STORE is on, then flattens the DICOM Content Sequence. JSON/CSV export includes Findings and Impression as columns plus the full report text. No language model.
- **Dicomtag Analytics**: **Count patients by name** button on a Study-level query result. Patient Name, Modality, Study Date and Tamar Practice Settings Code (the radiology department, `07a3,105c`) are already Study-level search keys, so no new query level was needed — filter on those, run the query, then click Count patients by name to see a table of "starts with A: 500, starts with B: 1300, ..." counts, one row per first letter of the patient's family name (`#` for anything non-alphabetic). Counts distinct patients (deduplicated by Patient ID, falling back to Patient Name when Patient ID is blank), not study rows, so a patient with three studies in range counts once. Starts from the already-exported result (no extra C-FIND) and shows an approximate count immediately; if that first pass hit the 2000-record display cap, it automatically re-runs the same query in the background asking only for Patient Name/ID (so it stays light) with the cap lifted to 50000, and replaces the approximate numbers with an exact count once that returns — no need to narrow the date range and click again by hand. Only if even that uncapped pass is exceeded (50000+ matching studies) does it fall back to telling you to narrow the filters yourself.
- **Dicomtag Analytics** Query: DICOM keys are a compact tree (checkboxes kept); results sit on the right of the filters so tables can use the remaining width. Query duration is folded under Timing. Stop cancels an in-flight query in the browser. Study Date is required at Study level.
- Dicommunication and Dicomtag Analytics share a white admin-app shell: A mark in the top-left (full-palette aurora clipped to Sansation A), left menu, white panels. Dark and Professional remain in the theme menu.
- **Dicomtag Analytics**: own Start-menu tool from the Dicommunication installer (formerly C-FIND Advanced). Query Vue PACS with Study Root C-FIND at Study / Series / Image, including optional ELSCINT1 keys. **Tamar Assign To Doctor** is a confirmed matching key on Vue 12.2.8 (used with Modalities in Study); other Vue tags stay experimental. Shared config with Dicommunication; no other Test tools in that window.
- Sidebar is a two-level tree (Test tools → Connectivity / DIMSE / HL7). Click **Test tools** (or a category) to fold it out; groups start folded. **About** and **Help** sit on one compact row.
- PDF to DICOM: checking **Generate Patient Name / ID** fills those fields immediately. Scan and every upload path accept **PDF only**.
- Sidebar **About** and **Help** buttons: About shows the running version and this installation; Help is the in-app administrator guide (each screen and tool, including HL7 Advanced troubleshooting).
- **PDF to DICOM** (`pdf-store`): import PDF files, a ZIP of PDFs, or a local directory; wrap each as Encapsulated PDF Storage; optionally C-STORE to a PACS.
- App chrome matches the quiet marketing site: squared corners (no pills), opaque panels instead of glass, slate-grey light mode, near-black dark mode, and bright cyan / amber / teal / rose accents on metrics, nav, and primary actions.
- HL7 send: MSH-10, ORC-1, OBR-31, and OBR-25 stamps sit behind **Advanced troubleshooting**, with a short note on what each field actually changes (and that an ACK is still not a PACS update).
- HL7 send: the UI can set ORC-1 to XO (change order) and put OBR-31 into a CE `id^text`. A new MSH-10 alone is not an order update. The Send result also repeats OBR-25 and adds a Hint when an ACK is likely not a PACS update.
- HL7 send: XO also stamps ORC-9. OBR-31 CE now fills an empty identifier (`arnout.pro^arnout.pro SEH` instead of `^arnout.pro SEH`). A **Set OBR-25 to SC** checkbox tests the usual completed-exam skip; an ACK still does not rewrite images already in PACS.
- HL7 send: **ORC-1 on change** can stamp Vue / IS Link **SC** (update order). XO is not in the Vue order-control table; a Mirth ACK is not Vue applying the order.
- HL7 send: if Vue **IS Link is empty** after an ACK, Host/Port is not the IS Link listener. The ACK step shows **MSH-3** (who answered). Hints say to send to IS Link’s listen host:port from IS Link Configuration — no Mirth access required.
- HL7 send: Philips Vue **10010** can be the HL7 VIP **and** IS Link’s Listener Port Number. The Listeners page is settings, not the queue — look at **Queues & Notifications**. Control Port (often 2112) is not MLLP. The transcript also repeats **MSH-5 / MSH-6**.

## 0.3.0

HL7 send, native desktop window, Mac DMG, app icon, denser chrome, and MSI GitHub Packages.

- HL7 send: paste or save an HL7 v2 message and send it over TCP (MLLP by default) to a host:port. This is a sender, not a message analyzer; the result shows the raw ACK / MSA-1.
- HL7 send: the message box wraps long pipe-delimited lines. A Segments view shows one row per segment (MSH, PID, OBR, …); Raw is the full paste.
- HL7 send: the Send result shows MSH-10, ORC-1, and OBR-31 as they went on the wire. The UI can stamp a new Message Control ID so a resend is not treated as a duplicate. An ACK still only means the engine accepted the bytes.
- Frozen Mac and Windows builds open the UI in a native app window (WKWebView / Edge WebView2), not a Safari or Chrome tab. `--browser` still uses the system browser; `--no-browser` is server-only.
- Mac DMG: Finder launches show the native window. PyInstaller argv emulation was fighting Cocoa/pywebview (Dock icon and a live process, no window). Frozen launches also append `~/.dicommunication/launch.log`.
- Dock, Finder, the Windows Start menu, and the native window use the **Sansation Bold** capital A (same letter as the watermark), not a geometric stand-in and not PyInstaller’s floppy-disk icon.
- macOS Apple Silicon DMG: CI freezes `Dicommunication.app` and attaches `dicommunication-<version>-macos-arm64.dmg` to `v*` GitHub Releases. The already-cut `v0.2.0` tag can get a DMG without a new version: **Actions → macOS DMG → Run workflow** with `release_tag=v0.2.0`.
- Version tags also publish `dicommunication.msi` to GitHub Packages (NuGet). The already-cut `v0.2.0` MSI can be wrapped without rebuilding: **Actions → Windows MSI → Run workflow** with `nuget_from_release=v0.2.0`.
- Page chrome is denser across Dashboard, Configured nodes, Testbench, Worklist, and tool pages: tighter headers, panels, forms, tables, and buttons. Logs still uses leftover height for the live viewer.
- Log level and other `<select>` menus use the themed glass panel in Dark mode, so the OS does not paint a white popup.
