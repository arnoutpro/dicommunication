What this application is

Dicommunication is a trusted-network DICOM and HL7 connectivity workstation for IT staff and PACS administrators. Configure this computer as a DICOM Application Entity, register remote nodes (PACS, Orthanc, RIS/MWL, modalities), optionally impersonate extra calling AE Titles, and run the checks a connectivity ticket actually needs.

It is written by arnout.pro (Arnout). The web UI is FastAPI + HTMX. DICOM uses pynetdicom / pydicom. Frozen Windows and macOS builds open the UI in a native window; Docker Compose and a local Python process serve the same UI in a browser at http://127.0.0.1:8080.

This is not a PACS, not an image viewer, and not a replacement for a vendor modality simulator. It does not store a clinical archive. There is no web login — treat port 8080 like a diagnostic console on the PACS VLAN, a lab, or a jumphost.

Open Help for how each screen and tool works, including C-ECHO versus C-STORE versus Study Root C-FIND versus Modality Worklist, and HL7 send to Vue / IS Link.

What it does and does not do

It does It does not
Present a calling AE Title (this workstation, or a virtual identity such as CT1) Implement C-MOVE or C-GET (those remain plugin slots)
Associate with a remote AE and show which SOP Classes were accepted or rejected Store a real archive of clinical images
Send Verification (C-ECHO), a tiny Secondary Capture (C-STORE), Study Root Query/Retrieve C-FIND, and Modality Worklist C-FIND Speak DICOM TLS, or authenticate the web UI
Optionally serve a local web worklist as an MWL SCP on the listen port Parse, validate, or map HL7 fields — paste a message and send it
Send an HL7 v2 message over TCP (MLLP by default) to a host:port Promise that an HL7 ACK updated the PACS — ACK only means the listener accepted the bytes
