What this is

This window is {{ product_name }}. It ships in the same Dicommunication installer. It is not the workstation: there is no PING, C-STORE, PDF, HL7, Testbench, or worklist here.

Both tools share the calling AE Title and remote nodes in the data directory. Add the Vue Q/R SCP once; Dicommunication C-ECHO and this query page use the same record.

This searches stored studies with Study Root Query/Retrieve FIND. It is not Modality Worklist. After a Study query, List SR reports runs Series C-FIND with modality SR for every study in the table. Retrieve report text is one Study Root C-MOVE per listed report onto this AE; it is not C-GET, and it is not limited to the first exam.

Query

Open

Study Root FIND at Study, Series, or Image. Keys sit in a compact tree on the left (checkbox = return column; typed value = matching key). Results occupy the right pane so wide tables stay readable. Study Date is required at Study level (a day or a DICOM range). Stop cancels the browser wait; query times sit in a folded Timing pane with the association log.

  • Hierarchical FIND — not relational. Series keys unlock after Study Instance UID is filled. Image keys unlock after Study Instance UID and Series Instance UID. Vue PACS documents this the same way.
  • Some keys stay locked until another field is present. Example: Repetition Time is an MR series key, so it stays unavailable while Modality is CT.
  • Click a result row to copy parent UIDs into the next level (Study → Series → Image).
  • The result table is column-aligned. Copy table puts tab-separated rows on the clipboard (Excel). Download CSV and Download JSON export the same records.
  • List SR reports takes every Study row in the table (not a clicked row) and queries Series with modality SR (same Study Instance UID, different Series Instance UID).

Structured reports

Radiology reports stored as DICOM SR are a series inside the study. They keep the Study Instance UID and get their own Series Instance UID. Typical workflow:

  1. Study query: today’s date, Modalities in Study CT (or whatever you need).
  2. List SR reports — Series C-FIND, modality SR, for every study in the result table (capped at 200 studies). The button shows how many studies will be queried. Clicking a row does not limit this to that exam.
  3. Retrieve report text — C-MOVE every listed SR (the button shows the count) to this workstation’s AE Title. Each report is a separate C-MOVE, so Vue cannot stop after the first exam. The Content Sequence is flattened into concept / type / value rows. No language model.

Retrieve needs Accept C-STORE (Structured Reports) on Local DICOM AE, and Vue must list that AE Title as a C-MOVE destination at this host:port. Imaging series are not stored. A retrieve asks for up to 200 SR series. Each report is C-MOVEd on its own association; the summary is Retrieved N of M. The result shows Findings and Impression as report text; the DICOM Content Sequence tree is under a fold. Download JSON includes those fields, plus sr_text (the full report) and the Content Sequence tree.

Vue PACS (ELSCINT1) keys

Collapsed lists of Tamar private study and series tags (status UNREAD, assign-to-doctor, procedure code, original storing AE, …). They are off by default. Vue’s C-FIND DCS does not list them. Tamar Assign To Doctor (07a1,1042) is a confirmed matching key on Vue 12.2.8 (used with Modalities in Study, for example CT). Other Vue tags may still be omitted. Grid Token sequences are not sent.

Configured nodes

Open

Local DICOM AE is this workstation’s listen identity. Turn on Accept C-STORE (Structured Reports) on that page to retrieve SR text. Vue must list that AE Title (not a virtual Present as title such as a viewer) as a C-MOVE destination at this host:port. Remote nodes must include the Vue Q/R SCP (AE Title, host, port). Virtual AEs impersonate a modality calling AE when Vue requires it for C-FIND. C-MOVE still uses the listen AE Title as destination.
