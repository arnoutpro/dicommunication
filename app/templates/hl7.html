Sending to Philips IS Link?
  • Host and Port are the listener's Host IP and Port Number under IS Link Configuration → Listeners (often 10010). Not a VIP or a Mirth box.
  • The Control Port (often 2112) is not MLLP; don't send to it.
  • After a send, look in Queues & Notifications; the Listeners page is settings, not the queue. Start the Listener process if IS Link asks.
  • The ACK's MSH-3 says who answered. Encoding Cp1252 matches Latin-1 for ASCII HL7.

3Adjust before sending

Fields rewritten on send

These only rewrite fields the message already has; they never add an ORC or OBR.

Stamps a fresh MSH-10 and MSH-7 so a resend counts as a new message.

Details

MSH-10 is the unique id of this send. Many engines ACK a repeat of the same id and then ignore it as a duplicate. This does not change order-control codes.

Sends an update for an accession that already exists, instead of a new order.

Details

Overwrites ORC-1 with the code above and stamps ORC-9 (transaction time). It won't add an ORC if the message has none. Repeating NW (new) is usually ACKed and skipped.

The IS Link specification for Vue 12.2.8 defines only NW (add), SC (update) and CA (cancel). In standard HL7, SC means "status changed" and XO is the change request; Vue often ignores XO while Mirth still ACKs.

IS Link replaces the whole segment on an update: a field that had a value and is empty in a later message is deleted. Send the complete ORC and OBR, not only the fields you want to change.

Sets OBR-31 to code^text. Leave both empty to keep the current reason and only fix its format.

Details

OBR-31 is a CE of id^text. A space in the identifier, or an empty id (^text), is often ignored; with both fields empty the existing value is rewritten to firstword^full text. HL7 delimiters (| ^ ~ \ &) typed here become spaces. In HL7 2.3.1, which IS Link uses, OBR-31 is a CE (identifier^text^coding system).

The IS Link specification lists DICOM (0040,2010) for OBR-31, but in DICOM that tag is Order Callback Phone Number, so that looks like an error in the document. The reason for a study is (0040,1002) Reason for the Requested Procedure or (0032,1030) Reason for Study; which one Vue fills is not confirmed. The description in the Vue UI is often Study Description from the images (C-STORE) or OBR-4.2, not this field.

Test only. For example, to see whether Vue skips updates to an exam that is already final.

Details

OBR-25 is the result status (HL7 table 0123: single letters such as P preliminary, F final). SC is not in that table; it is an order status and is offered because it is the Vue test this option started as. Vue maps OBR-25 to DICOM Interpretation Status ID (4008,0212), the same as OBX-11.

ORC-5 is the order status (table 0038); the IS Link specification lists only SC (scheduled) and CA (cancelled). Neither field is added if the message has no OBR or ORC, and this is not ORC-1 SC (Vue update order). It doesn't rewrite images already stored in the PACS.
