What this is (and is not)

Dicommunication is a trusted-network admin workstation. Use it on the PACS VLAN, a lab, or a jumphost that can reach DICOM and HL7 ports. Configure this machine as a DICOM Application Entity, register remote nodes, impersonate extra calling AE Titles when a modality identity is required, and run the checks a connectivity ticket actually needs.

It is not a PACS, not a viewer, and not a replacement for vendor modality simulators. It does not keep a clinical image archive. Frozen Windows (MSI) and macOS (DMG) builds open the UI in a native window. Docker Compose and a local Python process serve the same UI in a browser. The page only exists after the backend is already running — you cannot install Python from inside this UI.

See About for the version of this process, the calling AE Title, the listen port, and the data directory on this computer.

Security on a trusted network

The web UI has no login. Docker Compose therefore publishes port 8080 on 127.0.0.1 only; start it with DICOMM_HTTP_BIND=0.0.0.0 to reach the UI from another machine, and put an authenticating reverse proxy in front of it when you do. Do not publish port 8080 to the internet without one. Do not point it at production archives unless you intend to send the test C-STORE instance (patient ARNPRO^TESTBENCH / ID ARNPRO-TEST) or real Encapsulated PDF documents you import.

DICOM and HL7 are sent in the clear unless you terminate TLS elsewhere. HL7 send transmits whatever you paste. PDF to DICOM reads files you upload, ZIP contents, and any workstation path you type — treat that like a diagnostic console, not a public website.

The user interface

The left sidebar stays open. Nested groups are a two-level tree: Test tools → Connectivity (and DIMSE, HL7), Configured nodes → Local AE / Virtual AEs / Remote nodes. Groups start folded. Open a chevron to expand; the section that contains the current page stays open. Your open/closed state is remembered in this browser. Dashboard is the home page. Logs is the live application log.

The top bar holds the arnout.pro A mark and the product name. The left menu is Dashboard (or Query in Vue PACS Database Analytics), configured nodes, logs, and — in Dicommunication — Test tools. At the bottom of the sidebar, About and Help sit on one row and open these documentation pages. The theme control switches Light, Dark, Follows device setting, or Professional dark. New installs open in Light. The AE chip is this workstation’s calling AE Title; the line under it is the listen port and how many virtual identities you have saved.

Most tool pages use HTMX: the form posts without a full page reload, and the result panel updates in place. Long DIMSE operations can take tens of seconds; wait for the result rather than clicking again.

DICOM services this tool distinguishes

A working C-ECHO (or Orthanc answering MWL in its own UI) does not mean Storage or Query/Retrieve will succeed. These are different SOP Classes. That difference is the point of the Testbench.

UI name DIMSE SOP Class What it actually tests
C-ECHO C-ECHO Verification 1.2.840.10008.1.1 Association plus a DICOM ping. Connectivity only.
C-STORE C-STORE Secondary Capture Image Storage Can the peer receive an instance? Orthanc usually yes; an MWL-only RIS usually no.
PDF to DICOM C-STORE Encapsulated PDF Storage 1.2.840.10008.5.1.4.1.1.104.1 Wrap a PDF as a DICOM document (modality DOC) and store it. A peer that takes Secondary Capture may still reject Encapsulated PDF.
C-FIND C-FIND Study Root Query/Retrieve FIND Search stored studies in a PACS archive at STUDY level. Zero matches can still be a successful Q/R C-FIND.
Vue PACS Database Analytics C-FIND Study Root Query/Retrieve FIND Own Start-menu tool from this installer (formerly C-FIND Advanced). Study, Series, or Image plus Vue ELSCINT1 keys. Not in the Dicommunication sidebar.
MWL C-FIND / Worklist C-FIND Modality Worklist 1.2.840.10008.5.1.4.31 Search scheduled procedures, not the archive.

MWL C-FIND and the Worklist page are the same SOP Class. Study Root C-FIND is not. Orthanc without the worklist plugin typically accepts Verification, Storage, and Q/R, then rejects MWL. The Testbench and Worklist results show accepted vs rejected presentation contexts so that is visible.

Calling AE vs Scheduled Station AE

Two AE Titles matter on a worklist query, and they are easy to mix up:

  • Calling AE Title — who you are on the association. The remote must allow this AE (Orthanc DicomModalities, vendor “known AEs”, and so on).
  • Scheduled Station AE Title — a query key in the MWL identifier. Modalities normally ask for procedures scheduled to their own station (CT1, MR1, …).

On Worklist, Testbench, and each DIMSE tool, Present as chooses who you are:

  • (workstation) — the Local DICOM AE Title from Configured nodes
  • a virtual identity — calling AE plus that identity’s station / modality defaults

The result header shows as CT1 (or whatever calling AE was used). Every virtual calling AE must be allowed on the remote, the same way the workstation AE is.

Dashboard

Open

The home page summarises this workstation’s calling AE, how many remote nodes you have registered, and which test tools are loaded. The remote-node table is the same list as Configured nodes, with a last C-ECHO badge when the C-ECHO board has been run. Shortcuts go to Testbench, PING, and C-ECHO for that peer.

Recent results is a short timeline of the last tool runs (capped in storage at 200). Start with Network PING, then C-ECHO, then the DIMSE service you actually care about. A green C-ECHO here does not mean Storage or MWL will work.

Configured nodes

Open

This is the station identity: this workstation, virtual calling AEs, and remote DICOM nodes. Settings are saved on disk in the data directory and kept when you rebuild Docker or upgrade the MSI / DMG. The overview lists everything at a glance. Add or edit on the child pages: Local DICOM AE, Virtual AEs, Remote nodes. On Local AE, Advanced settings hides PDU, timeouts, and MWL SCP options.

Local DICOM AE

Open

This is the real Application Entity of this software: listen address, listen port, timeouts, and the default calling AE Title when you are not impersonating a modality. The listen port is one workstation AE. Virtual titles do not add extra SCP ports.

IP address 0.0.0.0 Bind / listen address. 0.0.0.0 listens on all interfaces. DICOM connections to remotes use the remote’s host, not this field.
Hostname empty Documentation only. Listen still uses the IP address.

Timeout 10 s ACSE, DIMSE, and network timeout (1–120).

Implementation version DICOMM_1 DICOM implementation version name (≤16 characters).

Virtual AEs

Open

A modality does not query worklist as a generic workstation. It associates as CT1 (calling AE) and asks for scheduled procedures for station CT1.

Virtual local AE titles are saved impersonation identities for outbound associations. Add as many as you need (CT1, MR1, US1, …). They do not listen. For Orthanc, add each one to DicomModalities.

Field Meaning
Display name e.g. CT scanner 1
Calling AE Title Who you are on C-ECHO, C-STORE, C-FIND, and MWL
Station AE Title Worklist query filter. Empty means “same as calling AE”.
Default modality Optional MWL / Q/R filter (CT, MR, …) filled when you pick this identity
Notes Room, vendor, Orthanc modality key — not sent on the wire

Remote nodes

Open

A remote is any peer you want to test: PACS, Orthanc, RIS/MWL, modality, VNA, or a vendor test SCP. From Docker, a PACS on the same Mac or Linux host is usually host.docker.internal.

Display name Label in the UI
AE Title Called AE Title (what you send as the called AE on associate)

Logs

Open

The Logs page has two parts:

  • Amount and file size — log level (DEBUG, INFO, WARNING, ERROR), maximum size of the current file (1–50 MB), and how many rotated files to keep. Changes apply immediately to this process and are stored in config.json.
  • Log view — the tail of dicommunication.log, refreshed every two seconds. Download the current file, or clear it (rotated files stay).

INFO records startup, configuration changes, tool runs, and MWL SCP start/stop. That is the usual setting on a PACS workstation. DEBUG also records HTTP requests (except health, static files, and the live tail poll). The console window on Windows shows the same stream.

Testbench

Open

One form to send C-ECHO, C-STORE, Study Root C-FIND, or Modality Worklist C-FIND to a selected remote, optionally as a virtual AE. Use this when you need to prove which SOP Classes a peer actually offers, not just that the port answers.

  • C-STORE sends a 16×16 Secondary Capture: patient ARNPRO^TESTBENCH / ARNPRO-TEST, modality OT. Look that instance up on the PACS if Storage was accepted.
  • C-FIND is Study Root, STUDY level. Leave filters empty for a broad query. Optional: patient name/ID, accession, study date, modality (ModalitiesInStudy).
  • MWL C-FIND uses the worklist SOP Class and the identity’s station AE unless you override it.
  • The result lists SOP Classes negotiated (accepted vs rejected) plus returned/stored records and the association log.

The individual DIMSE tool pages under Test tools use the same engines. Testbench is the place to switch services on one remote without leaving the page.

C-ECHO board

Open

Runs Verification against every configured remote in one click (up to 8 in parallel). Uses the workstation calling AE, not a virtual identity. The Dashboard table picks up the last pass/fail badge from this board. Also available as POST /api/echo-board/run.

Use the board as a morning check that DICOM ports still answer. Then use Testbench (or the individual tools) for Storage, Query/Retrieve, or MWL on the node that matters.

Worklist

Open

/worklist is the table view for Modality Worklist C-FIND (1.2.840.10008.5.1.4.31). It is not Study Root C-FIND. Use the Testbench for C-STORE and Q/R C-FIND.

Query worklist

  • Source — local web worklist, or a remote node marked as providing Modality Worklist
  • Present as — workstation or a virtual AE
  • Filters — patient name (DOE* style), patient ID, accession, modality, station AE, scheduled date

Empty filters on a remote mean “return what the SCP is willing to send”. Presenting as CT1 fills station (and modality, if the identity has one) unless you override the fields. Zero rows with a Pass still means the SOP Class was accepted — check station AE, date, and Present as.

Local web worklist

Add scheduled procedures here. If Serve the web worklist over DICOM (MWL SCP on the listen port) is on under Local DICOM AE, a modality can C-FIND this workstation on the listen port (11112 by default). The local MWL SCP also answers C-ECHO. It uses the workstation AE Title, not virtual identities.

Network PING

Open

DNS resolve, ICMP echo, then TCP connect to the DICOM port of the selected remote. That TCP step is the same kind of check as PowerShell Test-NetConnection -Port; a separate Test-NetConnection tool would overlap. ICMP is often blocked on clinical networks; the TCP check is the useful layer-4 result. A successful TCP connect does not prove DICOM — only that something is listening. Follow with C-ECHO.

C-ECHO

Open

Verification SOP Class 1.2.840.10008.1.1. Associates with the selected remote as the chosen calling AE and sends C-ECHO. A pass means the peer accepted Verification and answered. It does not mean the peer will accept Storage, Study Root FIND, or Modality Worklist.

If the association is rejected entirely, the calling AE is not in the peer’s allow-list, or host / port / called AE are wrong. Check Configured nodes and the vendor “known AEs” list (Orthanc DicomModalities).

C-STORE

Open

Sends one tiny Secondary Capture Image Storage instance. This tests whether the peer is a Storage SCP for that SOP Class — not whether your real modality’s SOP Class (CT, MR, US, …) will be accepted. Many archives accept Secondary Capture; some modality-only gateways do not.

The instance is identifiable on the PACS: patient ARNPRO^TESTBENCH, ID ARNPRO-TEST, modality OT. Do not send it to a production archive unless that is intentional. If C-ECHO works and C-STORE fails, the peer is not a Storage SCP for Secondary Capture (or that SOP Class is disabled).

PDF to DICOM

Open

Import PDF bytes, wrap each file as Encapsulated PDF Storage (SOP Class 1.2.840.10008.5.1.4.1.1.104.1, modality DOC), then optionally C-STORE the instances to a selected PACS. This is not the Testbench Secondary Capture image, and it does not rasterize PDF pages into pixel data.

  • PDF files — one or more .pdf uploads only. Other types are rejected.
  • ZIP of PDFs — only .pdf entries are used. Path traversal (..), __MACOSX, encrypted entries, and non-PDF files are skipped. Caps: 25 MB per PDF, 40 files, 40 MB ZIP, 80 MB uncompressed.
  • Folder of PDFs — the browser’s directory picker. Only .pdf files are kept.
  • Directory on this workstation — a path this server can read. … opens a native folder dialog on this workstation (needs a desktop session). Scan lists PDF files only; other types are ignored. Hidden files and the filesystem root are skipped / refused. There is no login.
  • Patient Name / Patient ID — required (marked *) unless you generate them. Checking Generate fills the field with a value such as ARNPRO^PDFxxxx / PDFxxxxxxxx. Optional accession, study description, and document title (defaults to the file name).
  • Generate Patient Name / ID — fills one shared identity for the batch (useful when you do not have a real patient). Unique patient per PDF derives Name and ID from each file name so a folder of reports does not land as one person on the PACS.
  • Same study — on by default. All PDFs in the batch share one Study Instance UID and Series Instance UID.
  • Store on PACS — C-STORE Encapsulated PDF Storage. Uncheck to encapsulate only and see the SOP UIDs. The peer must accept that SOP Class; a green C-ECHO or Secondary Capture C-STORE is not enough.

Look the study up on the PACS with the Patient ID you typed. If association opens but Encapsulated PDF is rejected, enable that SOP Class on the archive (Orthanc usually accepts it with Storage).

Study Root C-FIND

Open

Query/Retrieve Study Root FIND — search stored studies in a PACS archive. This is not Modality Worklist. Leave filters empty for a broad STUDY-level query. Optional filters: patient name, patient ID, accession, study date, modality in study.

Zero matches with a Pass still means the SOP Class was accepted and the query succeeded. If C-ECHO works and Study Root C-FIND fails, the peer is not a Q/R SCP (or that information model is not offered). Use Worklist / MWL C-FIND for scheduled procedures. For Series or Image keys, or Vue Tamar tags, open Vue PACS Database Analytics from the Start menu (or /vue/).

Vue PACS Database Analytics

This installer ships a second tool, Vue PACS Database Analytics, that used to live here as C-FIND Advanced. It is not in the Dicommunication Test tools list. Open it from the Start menu (Windows) or at http://127.0.0.1:8080/vue/. It shares this workstation’s calling AE and remote nodes. The analytics window has Query, Configured nodes, Logs, About, and Help — no PING, C-STORE, HL7, or worklist.

Study Root FIND at Study, Series, or Image, including optional Tamar / ELSCINT1 keys. Hierarchical FIND: Series needs Study Instance UID; Image needs Study and Series Instance UID. Tamar Assign To Doctor (07a1,1042) is a confirmed matching key on Vue 12.2.8 (used with Modalities in Study, for example CT). Retrieve is C-MOVE; this tool does not send C-GET or C-MOVE.

MWL C-FIND

Open

The same SOP Class as the Worklist page: Modality Worklist Information Model FIND 1.2.840.10008.5.1.4.31. Use this single-tool page when you already know you want MWL, or use Testbench to compare it with Study Root on the same remote.

Station AE and modality defaults come from Present as. Orthanc without the worklist plugin typically rejects this SOP Class even when Verification and Storage succeed — that is expected, not a bug in this tool.

HL7 send

Open

Sends an HL7 v2 message to a TCP endpoint. It is a sender, not an analyzer: paste (or save) the pipe-delimited text and ship it. The editor shows one segment per row (toggle Raw for the full paste). Long lines wrap. Newlines become CR on the wire.

  • Host / port — the HL7 listener, not the DICOM port. Typical engine ports are 2575 or 6661, not 104 / 4242.
  • Framing — MLLP (0x0B … 0x1C 0x0D) is the default. Raw TCP is there for engines that do not wrap.
  • ACK — if the peer replies, the result shows the raw ACK, MSA-1 (AA / AE / AR), and ACK MSH-3 (who answered). An ACK is not a promise that PACS applied an order update.
  • Saved drafts live in hl7_messages.json next to config.

Advanced troubleshooting

Collapsed by default. Optional stamps applied to the paste before send. They do not invent missing ORC / OBR segments. The UI defaults below still apply if Advanced stays closed.

  • New Message Control ID (MSH-10) — on by default in the UI. A new Message Control ID so a resend is not treated as a duplicate. The same MSH-10 is often ACKed and ignored.
  • Change existing order (ORC-1) — on by default. Overwrites ORC-1 (see the control next to it) and stamps ORC-9. It does not invent an ORC. Repeating NW is usually ACKed and skipped.
  • ORC-1 on change — Philips Vue / IS Link uses SC to update an order (NW new, CA cancel). XO is generic HL7 change; Vue often ignores it while Mirth still ACKs. This is not OBR-25 SC.
  • OBR-31 as CE text — on by default. Reason for Study is id^text. Vue maps OBR-31 to DICOM (0040,2010), which may not be the study description you see in the Vue UI (that is often OBR-4.2 / C-STORE).
  • Set OBR-25 to SC (in progress) — on by default, test only. That is result status, not Vue’s ORC-1 SC. Also sets ORC-5 to IP. An ACK does not rewrite stored images.

The Send result repeats MSH-10, MSH-5 / MSH-6, ORC-1, OBR-25, and OBR-31 as they went on the wire, plus a Hint when the ACK is likely not a PACS update.

Philips Vue PACS + IS Link

The ACK you see is from whoever answers on Host/Port. On Vue, IS Link Configuration → Listeners shows Port Number (often 10010) and Host IP. That Listeners page is settings, not the inbound queue. Control Port (often 2112) is not MLLP. Encoding Cp1252 matches Latin-1 for ASCII HL7.

  1. Send to the Listener Host IP:Port Number. After Add/Edit Listener, IS Link reminds you to start the Listener process.
  2. Look at Queues & Notifications, not the Listeners form. A message there means routing worked; then ORC-1 SC, accession, and OBR-31 can matter.
  3. Still empty with connection refused / timeout: wrong Host IP, Listener down, or this workstation cannot reach that VLAN.
  4. Still empty but you got an ACK: ACK MSH-3 is who answered. If it is Mirth/IBE, Host is not this IS Link. MSH-5 / MSH-6 must match what IS Link accepts.
  5. Vue order control is NW (new), SC (update), CA (cancel). XO is not in that table. Match the accession Vue already has: ORC-3 / OBR-3 and often OBR-18.
  6. Updating an existing study may also need Vue’s ZDS Study Instance UID. HL7-PACS Field Mapping in that same tree decides which ORM fields actually overwrite.

Reading accepted vs rejected SOP Classes

After a DIMSE association, the result lists presentation contexts the peer accepted and those it rejected. Read that list before you trust a green/red summary:

  • Accepted Verification / Secondary Capture, rejected Encapsulated PDF — C-STORE test image works; PDF to DICOM will not. Enable Encapsulated PDF Storage on the archive.
  • Accepted Verification / Storage / Study Root, rejected MWL — stock Orthanc without the worklist plugin. Query the archive with Study Root C-FIND; query a RIS (or enable the plugin) for MWL.
  • All requested SOP Classes rejected, or association aborted — called AE, host, or port wrong; or the calling AE is not allowed.
  • Pass with zero rows — the FIND SOP Class was accepted and the query succeeded. Empty is a filter / data problem, not a connectivity failure.

JSON API

The same operations as the UI are available over HTTP. GET /health returns {"status":"ok","version":"{{ app_version }}"}. Interactive docs: /docs.

Tool ids: ping, c-echo, c-store, pdf-store, c-find, c-find-advanced, mwl-find, hl7-send. hl7-send does not need a remote id; pass host, port, and message in options. pdf-store takes Patient Name / ID in options, plus pdfs (filename + content_b64), zip_b64, or directory, and send (default true). c-find-advanced takes level (STUDY, SERIES, IMAGE), values (DICOM keywords), and optional return_keys. DIMSE tools take remote_id and optional identity_id for a virtual calling AE. Worklist query source is local or a remote id.

This API has no authentication. Restrict it the same way you restrict the UI.

Talking to Orthanc

Typical Orthanc DICOM port is 4242. From Docker on a Mac, host is host.docker.internal.

  1. Add a remote: AE Title ORTHANC (or whatever Orthanc uses), host host.docker.internal or the LAN IP, port 4242.
  2. In Orthanc DicomModalities, allow this tool’s calling AEs — the workstation (DICOMM by default) and every virtual title you will impersonate (CT1, …).
  3. Testbench: C-ECHO should pass if the association is accepted.
  4. C-STORE / Study Root C-FIND usually pass on a stock Orthanc Storage / Q/R setup.
  5. MWL C-FIND passes only if the Orthanc worklist plugin (or equivalent) is enabled and that SOP Class is offered. Otherwise the Testbench shows MWL rejected. That is expected.
